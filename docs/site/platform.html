Orchestration, CI/CD and migration

Three simulators show how the platform around the Data Vault runs: Airflow moves one load date at a time, GitHub Actions builds only what a PR changes, and the same dbt project moves from Snowflake to Databricks. Press Step, click a pill to jump, or click any box to read what it does.

1. Airflow: one load date per run

Two DAGs. vdwh_ingest loads the raw files of one day and publishes an asset event. vdwh_transform starts on that event and builds the layers with Cosmos, one task per dbt model.

2. CI/CD: build only what changed

A PR builds the changed model and its children in its own schema ci_pr_N, and reads everything else from prod with --defer. After the merge the deploy builds prod and publishes the dbt docs.

3. Migration: one project, two platforms

The models contain no if target.type. Dispatch macros hold the platform SQL. A reconciliation model compares both platforms table by table before any consumer moves.
